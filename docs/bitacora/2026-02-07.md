## Decisiones

- El unico run activo por personaje se controlara por logica de aplicacion (no se usa indice parcial).
- El ledger guarda month_key (YYYY-MM) para agregaciones mensuales y happened_on para cap diario.
- Los estados de misiones y runs se modelan con enums y se castean en Eloquent.
- Se reutiliza el middleware existente `role:admin` dentro del grupo `auth` para acceso al panel.
- Se estandarizan stats base del boss con claves hp, damage y defense.
- items_json se edita con filas repetibles si existe tabla items; si no, se edita como JSON manual.
- En step 6, todas las opciones van al boss final (goes_to_boss=true, next_node_id null).
- Minimo 3 y maximo 4 opciones por nodo (se impide borrar si quedarian menos de 3).
- Si hay errores de validacion, la mision no se publica y se muestran en el panel.
- El cap diario recorta el evento de puntos (no se bloquea por completo).
- El debuff por wounds afecta solo el calculo del boss (no se persiste).
- El limite 0..12 aplica solo a stats base (no a stats totales).
- Stats base fuera de rango solo muestran aviso en ficha.
- Bonus de equipo se toma de character_equipment + items; montura suma bonuses si existe.
- stats_json legacy (fuerza/magia/defensa/velocidad) se usa como fallback si faltan keys en ingles.

## Stats por nivel

### Formulas

- HP: 1.35 + 0.12 * (level - 1)
- ATK: 1.00 + 0.06 * (level - 1)
- DEF: 1.00 + 0.05 * (level - 1)
- SPD: 1.00 + 0.03 * (level - 1)
- MAG: 1.00 + 0.06 * (level - 1)

### Reglas

- Base 0..12 solo para validar/avisar.
- Total = floor(base * multiplier) + bonus_equipo (sin cap a 12).
- Minimos: hp>=1, attack>=1, defense/speed/magic>=0.
- Si faltan stats base, se usan defaults 8 (solo vista).

### UI

- Ficha muestra bloques: Base, Multiplicadores, Totales y Desglose.

### Logica run

- Solo misiones publicadas.
- Un run activo/boss_pending por personaje (redirige al actual).
- Elegir opcion registra step, suma danger_score y wounds segun reglas.
- Abandonar marca status=abandoned sin recompensas.

## Abandono con XP parcial

- Disponible solo si el run esta en status=active y NO esta en boss_pending.
- Recompensa: XP parcial = floor(mission_reward.xp * 0.10).
- Si no hay reward o XP es 0, se registra XP parcial=0 pero se permite abandonar.
- Prohibido otorgar oro, items o puntos de raza en este flujo.
- Idempotencia: la XP parcial solo se otorga una vez por run (se bloquea con partial_xp_awarded_at).
- Se registra partial_xp_amount, partial_xp_awarded_at y abandoned_at.
- UI: boton "Abandonar (10% XP)" solo en runs activos antes del boss con aviso de que solo entrega XP.

## Boss pending (CTAs)

- En boss_pending se muestran acciones claras: "Enfrentar boss" y "Retirarse (10% XP)".
- Retirarse con XP parcial ahora permite status=active y status=boss_pending (sin oro, items ni puntos de raza).
- Idempotencia + transaction con lock en el run.
- Rutas nuevas para pantalla de boss y accion: GET /misiones/run/{run}/boss y POST /misiones/run/{run}/boss/action.

## Sprite del jugador en boss battle

- Characters incluye sprite_path (ruta publica) y accessor sprite_url con fallback a race->sprite_path y placeholder.
- boss_battle renderiza el sprite del jugador con asset() y fallback si falta el archivo.

### Pruebas manuales

- Abandonar 2 veces el mismo run no duplica la XP.
- Abandonar con reward.xp=0 entrega 0 XP y marca el run como abandoned.
- Abandonar en boss_pending no otorga XP parcial (se debe rendir en batalla).

## Boss final

### Config

- config/missions.php con tiers, multiplicadores y cap diario.

### Tier y multiplicadores

- Easy 0-5 (boss 0.85, puntos x1.0)
- Normal 6-11 (boss 1.00, puntos x1.1)
- Hard 12-15 (boss 1.15, puntos x1.25)
- Brutal 16-18 (boss 1.30, puntos x1.45)

### Resolver

- Determinista: compara power del personaje vs power del boss.
- Si faltan stats, se muestra mensaje "no se puede resolver".

### Recompensas y puntos

- Recompensas aplicadas una sola vez (rewards_applied_at).
- Puntos de raza con RacePointsEvent y cap diario por personaje si repeatable=true.

### Integraciones

- Gold/xp en characters (campos existentes).
- Items en character_items si existe tabla items; si no, se informa que no hay items.

## Publicacion de misiones

### Validaciones

- Exactamente 1 nodo inicio en step 1.
- Al menos 1 nodo por step 1..6.
- Todos los nodos alcanzables desde el inicio.
- Sin ciclos en el grafo.
- Cada nodo con 3 o 4 opciones.
- Step 1..5: next_node_id obligatorio y al step+1.
- Step 6: goes_to_boss=true y next_node_id null.
- final_boss_id obligatorio.
- MissionReward obligatorio.

### Errores (ejemplos)

- "Debe existir exactamente 1 nodo marcado como inicio."
- "Faltan nodos para el paso 4."
- "El grafo de nodos contiene ciclos."
